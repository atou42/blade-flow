# Blade Flow 上行图谱地图系统 Spec

## 目标

地图系统的目标不是把 Blade Flow 改成小关卡跑图，而是补上世界真实感、章节感和调试入口。

玩家应该感觉自己不是在连续打八场抽象战斗，而是在沿着上行刀路穿过风暴门、赤线猎场和无相高路。地图负责提供地点、势力、压迫感和选择语境；战斗结构仍然保持当前的快进快打。

这一版地图系统必须做到三件事。

第一，开局前能看见世界总图，并理解三幕是三处真实地点。

第二，每一幕开始和战斗间选择时，能用该幕地图强化行进感。

第三，提供清晰但不干扰正式流程的调试直达，允许直接从一幕、二幕、三幕开打。

## 非目标

本阶段不做大地图自由移动。

本阶段不把八场战斗拆成可点击的小关卡节点。

本阶段不做路线寻路、地图迷雾、地块占领、支线任务链。

本阶段不新增存档结构的大改。调试直达只作为开发入口，不作为正式进度系统。

## 核心设计

地图分两层。

第一层是世界总图，名字叫上行图谱。它显示天裂、山脉、城邦和上行刀路。玩家在这里看到三幕入口：风暴门、赤线猎场、无相高路。

第二层是章节图。每一幕有一张主图，作为该幕进入前、战斗间选择、Boss 预告的环境背景。章节图不承载小关卡点击，只承载当前幕的情绪、势力和行进状态。

正式玩家流程是：选择武器后进入上行图谱，点击或确认风暴门，进入一幕。每一幕开始前出现章节图，随后进入第一战。战斗之间仍沿用当前奖励、路线、事件和 Boss 预告流程，但这些 overlay 的视觉背景改成当前章节图，避免所有选择都像孤立弹窗。

调试流程是：在上行图谱里出现一个轻量调试区，可以直接进入风暴门、赤线猎场、无相高路。选择后设置 `actLevel` 和 `encounterIndex`，按该幕第一场进入战斗。调试直达必须明显标注为调试，不应伪装成正式解锁。

## 地图素材分配

运行素材目录是 `assets/art/world-map-v1/`。

原始素材目录是 `assets/generated/art/world-map-v1/raw/`。

`world-overview.webp` 用作上行图谱总背景。它有天裂、远山、城邦和上行路径，适合承载三幕入口。

`act1-storm-gate.webp` 用作一幕风暴门主图。它有山路、城门、断旗和风暴压迫，是第一幕入口、第一幕战斗间选择、风暴队长预告的默认背景。

`act2-redline-hunter-city.webp` 用作二幕赤线猎场主图。它有红线、废城、桥道和追猎感，是第二幕入口、赤线路线选择、赤线宿敌预告的默认背景。

`act3-black-moon-citadel.webp` 用作三幕无相高路主图。它有黑月、高塔、断崖和终局压迫，是第三幕入口、终局路线选择、无相刀影预告的默认背景。

`act1-sky-bridge.webp` 用作一幕断桥、追击险路或风暴门中段的分支氛围图。

`act2-mirror-corridor.webp` 用作镜廊、假抬手训练、镜侍和镜廊祭司相关事件的分支氛围图。

`forge-mountain-gate.webp` 用作锻刃炉、雪山炉、后续高层锻造点备用。

`lower-road-inn.webp` 用作下层驿站、休整、刀塾、新手入口或主菜单备用。

## 上行图谱界面

上行图谱是一个全屏 overlay，不替代当前战斗 HUD。

它的视觉应该像一张被打开的战术卷轴，底图是 `world-overview.webp`。画面上有三个清楚可点的地点牌：风暴门、赤线猎场、无相高路。

每个地点牌显示地点名、幕数、Boss 名和一句短提示。

风暴门显示：一幕，风暴队长，学会出手与停手。

赤线猎场显示：二幕，赤线宿敌，过去的习惯开始追你。

无相高路显示：三幕，无相刀影，你的胜法会反过来成为考题。

正式模式下，只有当前可进入的幕高亮。第一次开局只高亮风暴门。通关一幕后赤线猎场可用，通关二幕后无相高路可用。

开发模式下，三幕都可点。调试入口放在同一张图上，但视觉上要弱于正式入口。它可以是底部一排小按钮：调试：一幕、调试：二幕、调试：三幕。

地图入口必须适合手机竖屏。地点牌不能贴近底部 Home 区。底部至少留出安全距离，避免上滑误触。

## 章节图界面

章节图用于每一幕开始前展示。

它不是可互动地图，而是章节确认页。背景是当前幕主图，上面显示地点名、势力名、Boss 名、当前战斗进度和一句当前幕提示。

一幕显示风暴门、风暴军、风暴队长。提示是：风暴压下来了，别贪第二刀。

二幕显示赤线猎场、赤线与镜廊、赤线宿敌。提示是：赤线记住了你的左手。

三幕显示无相高路、黑月与无相门、无相刀影。提示是：你赢得太像昨天了。

章节图出现时不需要长动画。轻微淡入和地图光点即可。它应该在一秒内可跳过，不能拖慢复玩节奏。

## 战斗间选择的地图化

现有的路线选择、奖励选择、黑市、锻刃炉、Boss 预告都可以保留当前逻辑，但视觉上应该接入地图语境。

路线选择不再只像三个抽象选项，而是显示在当前章节图上的三个方向。稳路放在主路，险路放在偏侧路，锻刃或黑市放在特殊建筑位置。

奖励选择仍然是卡牌式选择，但背景使用当前章节图，并在顶部显示地点语境。比如一幕锻刃炉选择时，背景可用 `forge-mountain-gate.webp` 或风暴门叠加炉火纹理。

Boss 预告使用该幕主图，并突出 Boss 名、烙印和读招倾向。它不需要展示完整大地图节点，只需要让玩家知道自己正在走向谁。

这样做的重点是让玩家感觉每一次选择发生在一个地方，而不是发生在纯 UI 空间。

## 调试直达

调试直达必须满足开发效率，但不能污染玩家认知。

入口位置建议放在上行图谱右上角的小型调试按钮，点击后展开三枚按钮：从一幕开始、从二幕开始、从三幕开始。

选择某一幕后，系统需要执行一次干净的跑局初始化。

调试进入一幕时，`actLevel = 1`，`encounterIndex = 0`，装备使用当前已选装备。如果还没选装备，默认使用第一把装备。

调试进入二幕时，`actLevel = 2`，`encounterIndex = 0`，保留当前装备，给予一组最低可玩的基础成长，避免二幕因为没有任何奖励而变成错误难度。基础成长只用于调试，不写入正式解锁。

调试进入三幕时，`actLevel = 3`，`encounterIndex = 0`，保留当前装备，给予比二幕更高的基础成长，并设置对应 Boss 默认烙印。

调试直达必须在日志中写明：调试进入二幕，非正式进度。

调试直达不得写入长期 profile 解锁，不得影响每日种子记录，不得污染正式存档。

## 状态与数据建议

新增地图状态应该尽量轻。

建议增加 `state.mapOpen` 表示上行图谱是否打开。

建议增加 `state.pendingActIntro` 表示当前是否需要显示章节图。

建议增加 `state.devActSelect` 或使用现有调试器状态控制调试入口可见性。

建议在 `actMeta` 里补充地点信息，而不是新建分散配置。

`actMeta[1]` 增加 `placeName: "风暴门"`、`factionName: "风暴军"`、`mapImage: "act1-storm-gate.webp"`、`tagline: "风暴压下来了，别贪第二刀。"`。

`actMeta[2]` 增加 `placeName: "赤线猎场"`、`factionName: "赤线与镜廊"`、`mapImage: "act2-redline-hunter-city.webp"`、`tagline: "赤线记住了你的左手。"`。

`actMeta[3]` 增加 `placeName: "无相高路"`、`factionName: "黑月与无相门"`、`mapImage: "act3-black-moon-citadel.webp"`、`tagline: "你赢得太像昨天了。"`。

新增 `worldMapAssets` 配置统一保存 `world-overview.webp`、分支图和备用图路径。

不要把图片路径散落在 HTML 和多个函数里。

## 入口流程

当前 `showEquipmentOverlay()` 选择武器后直接 `startRun(equipment)`。

地图版流程应改为：选择武器后进入上行图谱，正式开始按钮进入风暴门。

为了减少改动风险，第一版可以保留 `startRun(equipment)` 的核心逻辑，新增 `showWorldMapOverlay(equipment)` 作为中间层。点击风暴门后再调用 `startRun(equipment)`。

通关一幕后，当前 `showActClearOverlay()` 点击继续会直接 `advanceAct()`。地图版应在 `advanceAct()` 后显示下一幕章节图，再进入下一幕第一战。

如果玩家从调试入口选择二幕或三幕，调用新的 `startRunAtAct(equipment, actLevel, options)`。这个函数复用 `startRun` 的初始化逻辑，但允许覆盖 `actLevel`、基础成长和 Boss 烙印。

## 性能要求

地图图片必须使用 WebP，不直接使用 JPG。

地图 overlay 打开前应预加载当前要展示的图。`world-overview.webp` 可以在菜单阶段预加载。当前幕主图可以在进入该幕前预加载。

地图图像不要使用大面积 CSS blur。手机上可以用暗色渐层、纸纹遮罩和轻量 vignette，但不能用高成本滤镜制造氛围。

地图 overlay 关闭时要移除多余 DOM，不能留下持续动画。

地图光点动画最多 3 到 5 个，且使用 transform 和 opacity，不使用 layout 改动。

地图系统不能引入战斗划卡卡顿。战斗中不加载新的地图大图。所有战斗间图像必须在 overlay 阶段完成加载。

## UI 标准

地图界面要像游戏内系统，不像开发菜单。

地点牌不能是现代按钮风格。它应该像地图上的印章、旗标或刀痕标记。

地点牌文字要少。地点名最大，Boss 名次之，提示句最小。

调试按钮必须更小、更克制，可以放在角落，不能抢正式入口的视觉权重。

手机竖屏时，三个地点入口需要纵向错位排列，不能挤在底部。

桌面宽屏时，可以让总图横向展开，但主要点击热区仍以竖屏体验为准。

所有交互热区至少 44px，避免地图点太小。

地图 overlay 底部必须留安全区，不能贴近 iPhone Home 条。

## 文案规范

地图上的文本要短，像地名和战术提示，不写解释段落。

推荐文本如下。

上行图谱：沿天裂而上，刀路会记住你的胜法。

风暴门：一幕，风暴队长，学会出手与停手。

赤线猎场：二幕，赤线宿敌，过去的习惯开始追你。

无相高路：三幕，无相刀影，你的胜法会反过来成为考题。

调试入口：调试直达，不记录正式进度。

进入一幕：进入风暴门。

进入二幕：进入赤线猎场。

进入三幕：进入无相高路。

## 验收标准

打开游戏后，选择武器不会直接进入战斗，而是先进入上行图谱。

上行图谱能显示总地图，且三幕地点名、Boss 名和提示清晰可读。

正式流程首次只允许进入风暴门。

调试入口能直接进入一幕、二幕、三幕第一战。

调试进入二幕时，界面显示二幕、赤线猎场、赤线宿敌；第一战敌人使用二幕缩放和二幕前缀。

调试进入三幕时，界面显示三幕、无相高路、无相刀影；第一战敌人使用三幕缩放和三幕前缀。

通关一幕后，不是无提示跳到下一幕战斗，而是先看到赤线猎场章节图。

通关二幕后，不是无提示跳到下一幕战斗，而是先看到无相高路章节图。

路线选择、奖励选择或 Boss 预告至少有一类 overlay 使用当前幕地图背景，证明地图已经进入战斗间流程。

地图界面在 iPhone 竖屏截图中不贴底，不遮挡 Home 区，不出现文字溢出。

地图图片在战斗中不会临时加载，划卡战斗没有新增卡顿。

关闭地图 overlay 后，DOM 中没有残留持续动画节点。

调试直达不会写入长期 profile 解锁，不影响每日刀路。

## 第一版交付边界

第一版只需要实现上行图谱、三幕直达、章节图和一类战斗间地图背景。

第一版不需要做完整动态路线节点。

第一版不需要给每一场战斗单独绑定一张地图。

第一版不需要把地图上传到 R2。如果进入部署阶段，再把 `assets/art/world-map-v1/` 一起纳入 WebP 上传清单，并更新 `visualAssetBase` 版本。

## 后续扩展

后续可以让 Boss 烙印反映在地图上。比如赤线越来越亮，镜廊裂纹越来越多，黑月越来越低。

后续可以让路线选择影响地图局部。选择黑市后地图出现黑日契约印，选择锻刃后地图出现炉火点。

后续可以给每一幕做二级图。第一幕有风暴门、断桥、锻刃炉；第二幕有赤线猎场、镜廊、红线黑市；第三幕有无相高路、黑月观星台、黑鼓刑场。

这些扩展都不能破坏核心原则：地图服务节奏和真实感，不把 Blade Flow 变成慢速跑图游戏。
