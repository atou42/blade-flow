# Card Selection Audio Spec

日期：2026-05-09

本文定义 Blade Flow 的卡牌选择类交互音效。范围是战斗外和半战斗外的选择卡，不包括战斗手牌出招音。战斗手牌已经由 `playerCardPress`、`playerCardRelease` 和方向动作音负责。

目标不是让每个按钮都有声，而是让玩家在手机上触摸、确认、取消和识别奖励风险时得到清楚反馈，同时不能制造首次触发卡顿。

## 设计原则

卡牌选择音效必须比战斗动作音更轻。它负责确认手指碰到了选项、选择已经成立、选项类型有什么性格，不负责制造攻击感。

同一类交互必须有一致的触感。武器、奖励、路线、存档和工具卡都可以共用轻触音，但确认音要分层。玩家听到后应能区分这是普通选择、奖励选择、路线风险、武器开局，还是不能选。

选择音不能抢 Boss 读招、破势、命中和死亡。所有卡牌选择音默认归入 UI 层，音量低于战斗动作音，尾音短，不堆长混响。

移动端优先。没有 hover 设计，不为鼠标悬停单独做音。只有触摸按下、松手确认、禁用点击、面板展开这些真实动作有声音。

## 首批音效清单

### `uiCardTouch`

用途：手指按下任意可选择卡牌。

适用：武器卡、奖励卡、路线卡、存档槽、调配器入口、版本记录入口、真机链接入口。

声音：极轻纸面压下声，带一点墨纸摩擦。时长 80-140ms。音量很低，只做触感确认。

限制：低功耗模式下可以跳过。连续快速点击时允许被截断，不排队。

### `uiCardConfirm`

用途：普通选择成立。

适用：工具卡、存档读取、调配器入口、版本记录入口、普通确认按钮。

声音：短纸响加小印章落点。时长 120-220ms。稳定、克制。

限制：不能像奖励，也不能像战斗命中。

### `uiCardReject`

用途：选项不可用或被拦截。

适用：未解锁训练、坏档锁定、不能保存、不能导出、非法移动端验收记录。

声音：短促纸边回弹，低频很少，带轻微干涩感。时长 120-180ms。

限制：不能像失败结算。它只是告诉玩家这次没成立。

### `uiWeaponSelect`

用途：选择开局武器并进入战斗。

适用：六把开局武器卡。

声音：纸卡确认后叠一声短刀鞘落点。时长 220-360ms。

限制：不播放完整武器签名音。武器签名只属于战斗出招。

### `uiRewardPerformance`

用途：选择表现奖励。

适用：战后三槽里的表现位。

声音：短亮拨弦和纸面泛光，速度快，像连击表现被盖章。时长 180-280ms。

限制：不能像胜利，也不能和会心音混淆。

### `uiRewardBuild`

用途：选择构筑奖励。

适用：战后三槽里的构筑位，包含遗物、天赋、配方、路线成长。

声音：稳一点的木质拨片加纸印，重心在中频。时长 200-320ms。

限制：不要太亮。它表达长期构筑成立，不表达爆发爽点。

### `uiRewardCorrection`

用途：选择修正奖励。

适用：治疗、降压、修正、休整类奖励。

声音：柔和纸刷和轻呼吸感，尾音干净。时长 220-340ms。

限制：不能像危险路线，也不能像失败后安慰音。

### `uiRewardRareSheen`

用途：奖励稀有度附加层。

适用：稀有、史诗、传奇奖励确认时叠加播放。普通奖励不播放。

声音：很短金属泛音或玉石轻响。稀有只一小点，史诗更亮，传奇可多一层高频闪烁。时长 120-260ms。

限制：这是附加层，不替代奖励确认音。不能每次奖励面板出现就响，只在确认选择时响。

### `uiPanelReveal`

用途：选择面板展开。

适用：武器选择、战后奖励、路线选择、Boss 预演、存档面板。

声音：纸卷轻展开，带极轻墨刷。时长 180-300ms。

限制：不在每次 render 时播放，只在新面板首次打开时播放。

## 触发规则

按下可选择卡牌时播放 `uiCardTouch`。如果同一次点击随后确认成立，松手或 click 事件再播放对应确认音。触摸和确认可以连续，但确认音必须更清楚。

武器选择播放 `uiCardTouch` 和 `uiWeaponSelect`。进入战斗后仍播放 `uiBattleStart`，但 `uiWeaponSelect` 的尾音不能盖住开战音。

奖励选择播放 `uiCardTouch`，再按奖励槽类型播放 `uiRewardPerformance`、`uiRewardBuild` 或 `uiRewardCorrection`。如果奖励稀有度不是普通，额外叠 `uiRewardRareSheen`。

路线选择播放 `uiCardTouch`，再播放现有 `uiRouteStable`、`uiRouteMapBranch` 或 `uiRouteDanger`。不新增路线确认音，避免重复表达。

不可用选项播放 `uiCardReject`，不播放确认音。错误原因仍由文字说明负责，音效只做失败触感。

面板展开播放 `uiPanelReveal`。如果面板是 Boss 预演，仍可播放现有 `uiBossPreview`，但两者不能同时很响；优先保留 `uiBossPreview`。

## 性能策略

这一批音效不能在触摸瞬间首次创建或首次解码。

第一次用户手势解锁音频后，进入后台预热队列。`uiCardTouch`、`uiCardConfirm`、`uiCardReject`、`uiWeaponSelect` 必须优先预热。奖励类和面板展开可以第二批预热。

预热策略必须分批执行。每个 idle 片段最多处理 1-2 个音频，避免一次性 decode 抢主线程。没有 `requestIdleCallback` 时用短 `setTimeout` 分批。

同源音频可以使用 Cache Storage 保存响应。运行时优先从 Cache Storage 取 blob，创建 object URL 后绑定到复用的 Audio 对象。不能在 pointerdown 到 pointerup 的输入关键路径里 fetch、decode、创建 Audio 或 decode 图片。

低功耗模式下，`uiCardTouch` 和 `uiPanelReveal` 可跳过，确认音和拒绝音保留。奖励稀有度附加层可跳过。路线风险音保留。

## 调试要求

`window.__bladeFlowDebug.audioState()` 需要继续返回最近 SFX。后续实现这一批时，应增加 UI 音频预热状态，至少包含每个卡牌选择音效的 `queued`、`loaded`、`cached`、`lastWarmupError`。

如果某个音频预热失败，交互时不能静默假装成功。可以跳过该音效，但 debug 里必须能看到错误。核心交互不能因为音频失败而阻塞。

## 验收标准

本地和线上都必须验收。

首次右滑、首次武器选择、首次奖励选择、首次路线选择、首次不可用卡牌点击都要单独测。

合格标准：

- 触摸关键路径里没有新音频请求。
- 触摸关键路径里没有首次创建 Audio。
- 触摸关键路径里没有大图 decode。
- 单次交互不产生 50ms 以上 long task。
- 390x844 手机视口下连续快速选择 10 次，`lastError=""`。
- 静音后不触发新音效，重新开启后继续使用已缓存对象。
- 低功耗模式下跳过装饰音，但保留确认、拒绝和路线风险音。

验收记录需要写入 `docs/verification/`，并标明本地 URL、线上 URL、Cloudflare 版本 ID、浏览器 console 结果和性能探针结果。
