# Blade Flow Boss 调试台 Spec

日期：2026-05-14

版本目标：做一个手机竖屏优先的 Boss 数值调试台，让开发和设计可以直接选择任意一幕、任意 Boss、任意成长状态，调整参数后立刻开打，并把完整配置导出给别人复现。

## 核心目标

当前最大问题不是没有参数，而是参数调整和实战体验断开了。要判断一场 Boss 战是否爽、是否有压力、是否能教会玩家，必须能快速完成这个循环：选 Boss、选玩家成长、改数值、挑战、失败或胜利、再改、导出。

调试台必须解决四件事。

第一，允许直接挑战每一幕的具体 Boss，不需要从正式流程一路打到那里。

第二，允许模拟玩家到达该 Boss 前已经获得的成长，包括固定奖励、可选奖励、武器路线、证据、遗物、卡牌变化和基础数值。

第三，允许调整 Boss、玩家、卡牌、后摇、读招、奖励、AI 行为和难度倍率，并且调整后能立刻应用到下一场战斗。

第四，允许导入、导出和复制完整参数包。导出的内容必须足够完整，别人拿到后能复现同一场测试。

## 非目标

这一版不做桌面专业编辑器。

这一版不做长期数值数据库。

这一版不做云端同步和多人协作。

这一版不允许调试配置写入正式 profile、正式解锁、每日成绩或玩家存档。

这一版不把所有内部状态都暴露成表单。只暴露能影响 Boss 体验和难度判断的参数。

## 设计原则

调试台是内部工具，但必须像游戏内系统。它不应该像浏览器后台，也不应该像临时 debug 表格。视觉上沿用水墨纸面、刀痕分割、地图和印章语言。

手机竖屏是主设计目标。所有核心功能必须能在 390 像素宽手机视口完成。桌面可以更宽，但不能以桌面为主。

调试台必须一屏一个任务。选 Boss 是一个任务，调参数是一个任务，选成长奖励是一个任务，导入导出是一个任务。不要把所有控件挤在同一个长页面里。

调试配置必须显式、可读、可复制。不能依赖本地隐藏状态补全关键字段。缺关键字段时必须拒绝导入，并说明缺什么。

调试进入战斗必须干净。每次从调试台挑战 Boss，都要从配置重新生成一场测试战，不能沿用上一场残留的 Boss 状态、手牌、后摇、音频、动画或奖励。

## 总体结构

调试台分三层。

第一层是 Boss 地图入口。它使用地图感来选择幕、地点和 Boss。这里解决“我要打谁”的问题。

第二层是全屏调试台。它是主工作台，负责调 Boss 参数、玩家成长、奖励包、手牌和难度预设。这里解决“我要用什么状态打”的问题。

第三层是战斗内轻量抽屉。它只用于战斗时查看当前配置、复制配置、重开本场和少量快速微调。它不能承载完整调参。

推荐入口是：主菜单或上行图谱里显示一个克制的“调试台”按钮。点击进入 Boss 地图。选择某个 Boss 后进入全屏调试台。点击“挑战此 Boss”进入战斗。战斗中可以打开轻量抽屉，重开、复制或返回调试台。

## 手机竖屏布局

### Boss 地图入口

Boss 地图是调试台的首页。它不做小关卡流程，只做 Boss 直达。

顶部显示“调试模式”和当前配置名。右上角放导入按钮，避免用户必须先进工作台才能粘贴配置。

中间按三幕分区展示 Boss。每一幕显示地点图、幕名、Boss 名、推荐玩家成长阶段和难度标签。Boss 节点可以纵向排列，不能横向挤压。

底部固定显示当前选中的 Boss 摘要，包括 Boss 名、幕数、默认奖励包、当前难度倍率和两个按钮：“进入调试台”“直接挑战”。底部按钮必须离手机 Home 区有足够安全距离。

Boss 地图的作用是给调试带来世界真实感。它不需要承载细参数。

### 全屏调试台

全屏调试台是主要工作区。竖屏下采用顶部固定选择区、中部分页内容、底部固定动作区。

顶部选择区显示幕、Boss、玩家成长阶段和当前预设名。这里可以横向滑动选择 Boss，但每次只突出一个当前 Boss。

中部分页分成四个页签：战斗参数、成长奖励、卡组手牌、预设导出。

战斗参数页只放影响实战节奏的数值，例如 Boss 血量、Boss 伤害、Boss 架势、Boss 护势层、Boss 出手节奏、真确认窗口、破招奖励、玩家出牌间隔、动作后摇、连击倍率、Boss 适应速度。

成长奖励页负责模拟玩家到达该 Boss 前的状态。它按“固定成长”“可选奖励”“路线烙印”“证据与遗物”分组。每组默认折叠，但当前已启用的奖励必须可见。

卡组手牌页负责设置武器、刀谱、起手牌、牌库变化和固定抽牌序列。第一版至少支持选择武器、选择起手奖励包、固定起手手牌、固定随机种子。

预设导出页负责保存、复制、导入和比较。它显示当前配置的可读摘要，以及完整 JSON 文本。

底部动作区固定两个主按钮：“挑战此 Boss”和“复制配置”。次要动作是“保存本地预设”“重置默认”。底部动作区不能遮住内容，也不能贴近 Home 区。

### 战斗内轻量抽屉

战斗内抽屉从右侧或底部打开，打开后仍能看到 Boss 和手牌。

它只显示当前 Boss、当前预设名、当前参数摘要、重开本场、复制配置、返回调试台。允许微调 Boss 血量倍率、玩家出牌间隔、Boss 出手速度这三个高频参数。

战斗内抽屉不能在划卡路径里创建大量 DOM。它必须提前存在或懒加载在非战斗输入阶段，避免重新引入划动卡顿。

## Boss 选择

调试台至少覆盖当前正式三幕 Boss。

一幕默认 Boss 是风暴队长。测试目标是基础教学、快刀破招、追身、右重兑现、下退安全。

二幕默认 Boss 是赤线宿敌。测试目标是习惯反制、假动作、延迟、追击惩罚和奖励压力。

三幕默认 Boss 是无相刀影。测试目标是混合判断、无相反制、长局压力和终局节奏。

如果当前代码里还有普通敌、精英或训练 Boss，调试台可以作为高级筛选暴露，但第一版主入口只突出三幕 Boss。避免工具一打开就变成敌人列表。

每个 Boss 节点必须提供默认配置。默认配置不能只给一个血量，而是要包含该 Boss 的幕数、推荐成长包、默认参数、Boss 行为组、默认音乐和场景背景。

## 玩家成长模拟

玩家成长必须按“到达这个 Boss 前合理获得什么”来建模，不能只给攻击倍率。

每一幕 Boss 都有一个推荐成长阶段。

一幕 Boss 默认使用开局武器、少量奖励、无高级遗物。它用于测试新手是否能学会系统。

二幕 Boss 默认使用一幕完成后的成长，包括一到两个核心奖励、一次路线烙印、少量证据或遗物。它用于测试玩家已经形成习惯后，Boss 是否能制造新问题。

三幕 Boss 默认使用两幕完成后的成长，包括成型武器路线、多个奖励、至少一个关键证据或遗物。它用于测试强构筑是否仍然有压力。

成长包分为三类。

“最低可玩”用于验证 Boss 不会因为玩家太弱而变成纯负反馈。

“推荐通关”用于判断正式玩家到达该 Boss 时的标准体验。

“高压测试”用于判断构筑偏弱、奖励偏差或玩家失误时是否还能学得明白。

用户可以手动覆盖成长包。手动覆盖必须标记为“自定义”，导出时保留完整差异。

## 参数范围

调试台第一版必须覆盖以下参数。

Boss 参数包括最大生命、当前生命比例、伤害倍率、架势值、护势层数、易伤持续时间、破势后停顿、出手速度倍率、AI 激进度、重复方向适应强度、假动作概率、后撤概率、地裂或抓取概率。

玩家参数包括最大生命、初始专注、出牌间隔、轻招后摇、追身后摇、快刀后摇、重刀后摇、撤身后摇、完美读招取消后摇、空挥惩罚后摇、连击倍率上限、撤身断连保留比例。

窗口参数包括快刀可破窗口、真确认持续时间、假抬手真确认延迟、后撤露空持续时间、重势破势窗口、地裂可撤窗口、地裂可破窗口。

奖励参数包括基础伤害倍率、破势奖励、完美破招补牌、追身保连奖励、撤身回手补牌、易伤伤害倍率、Boss 烙印权重。

卡组参数包括武器、刀谱、起手手牌、牌库、固定抽牌种子、奖励池开关、是否固定 Boss 动作序列。

所有数值控件都必须有合理范围、步进和当前值。范围不能靠浏览器默认值兜底。导入超范围值必须拒绝，不能悄悄夹到边界。

## 预设系统

系统内置三类预设。

“标准体验”代表希望正式玩家遇到的目标难度。

“教学验证”降低惩罚，放大反馈，用于确认玩家能学会 Boss。

“压力验证”提高 Boss 生命、出手压力和适应强度，用于确认高成长玩家不会无脑碾压。

本地预设只写入调试命名空间，不写入正式存档。预设可以保存多个，显示名称、Boss、幕数、创建时间和最后一次挑战结果。

保存预设前必须校验配置完整性。配置不完整时不能保存。

## 导入导出

导出格式是 JSON 文本。复制到剪贴板是主要路径。剪贴板失败时，页面显示可手动选中的完整文本。

导出的 JSON 必须包含：

```json
{
  "schema": "blade-flow.debug-boss-tuning.v1",
  "gameVersion": "v0.2.83",
  "createdAt": "2026-05-14T00:00:00.000Z",
  "label": "二幕赤线宿敌 标准体验",
  "target": {
    "act": 2,
    "bossId": "redline-rival",
    "encounterKind": "boss"
  },
  "playerBuild": {
    "equipmentId": "storm-katana",
    "growthStage": "act2-standard",
    "rewardPackId": "act2-standard-01",
    "enabledRewards": [],
    "deckOverrides": {},
    "openingHand": [],
    "seed": "debug-redline-standard-01"
  },
  "tuning": {
    "boss": {},
    "player": {},
    "windows": {},
    "rewards": {},
    "ai": {}
  },
  "notes": ""
}
```

导入时必须校验 `schema`、`target`、`playerBuild` 和 `tuning`。缺任何关键字段都不能进入战斗。

导入成功后必须显示一段可读摘要，让用户确认这是哪一幕、哪个 Boss、哪套成长和哪些关键参数。不能导入后直接改掉当前配置而不提示。

导入旧 schema 时第一版可以拒绝，并提示“不支持的调试配置版本”。不要做静默迁移。

## 战斗启动

从调试台点击“挑战此 Boss”时，系统必须执行一次独立初始化。

初始化内容包括：清空上一场战斗状态，设置目标 Boss，设置幕数和场景，应用玩家成长包，应用奖励，应用卡组和手牌，应用 Boss 参数，应用窗口和后摇参数，应用固定随机种子，预热本场需要的音频和 Boss 图像，然后进入战斗。

调试战斗必须显示清楚标记，例如顶部小字“调试战”。它不能显示为正式进度。

调试战斗胜利或失败后，结算只记录到调试台的最近结果，不推进正式 profile，不发正式奖励，不写每日成绩。

结算页要提供“再打一场”“返回调试台”“复制结果和配置”。结果导出应该包含胜负、用时、剩余血量、出牌次数、受击次数、破招次数、重刀命中次数、撤身次数、最高连击、Boss 打断次数和最近错误反馈摘要。

## 可学习性支持

调试台不能只让数值变难，还要帮助判断玩家是否能学会。

每场调试战结束后，至少显示三类摘要。

第一是压力摘要：玩家剩余血量、Boss 剩余血量、战斗时长、受击次数。

第二是策略摘要：四向使用次数、四向成功率、重刀空挥次数、撤身断连次数、完美破招次数。

第三是学习摘要：最常见失败原因、最常见 Boss 招式、玩家被惩罚最多的方向。

这些摘要可以先只在调试结算页显示，不需要进正式结算。

## UI 细节

参数控件优先使用滑杆加步进按钮。关键数值同时显示数字输入。布尔开关使用明确的开关，不用文字按钮假装开关。

奖励选择使用圆形印章或筹码，不做长列表。奖励很多时按类型折叠。

卡组和手牌使用小卡片预览，但不要求完整卡牌大图。重点是能看清方向、名字和用途。

危险数值用朱红，玩家成长用青绿，奖励和证据用金色，普通说明用墨色。不要把所有标签做成同一种颜色。

所有主要按钮的点击热区至少 44px。底部固定区必须加安全区 padding，避免 iPhone Home 手势误触。

页面不使用大面积 blur，不用复杂滤镜。调试台需要长时间反复使用，优先清晰、稳定、不卡。

## 性能要求

打开调试台不能影响正式战斗划卡性能。调试台 DOM 在关闭后要停用重动画。战斗中轻量抽屉不能触发大图加载。

进入调试战前必须预热本场 Boss 图像、场景图、BGM 和常用音效。预热发生在点击“挑战此 Boss”后的准备阶段，不发生在第一次划卡时。

参数变化不能每改一项就重建整场战斗。只有点击“挑战此 Boss”或“重开本场”时才重新初始化。

导出 JSON 可以即时生成，但不能每帧生成。只在打开导出页、复制或保存时生成。

## 安全边界

调试台只在 `?debug=1`、调试 profile 或内部入口开启。正式玩家流程不显示完整调试台。

调试配置、调试预设、调试结果都写入独立 key。不能和正式 profile 共用 key。

如果调试配置损坏，必须锁定该配置并提示原因。不能用默认配置假装导入成功。

如果配置引用不存在的 Boss、奖励、武器或卡牌，必须拒绝进入战斗，并列出缺失项。

如果当前版本不支持配置 schema，必须拒绝导入。

## 实现建议

建议把调试配置定义成独立模块，例如 `debugTuningConfig`。它负责默认配置、schema 校验、导入导出和本地预设。

建议把“从配置启动战斗”做成单独入口，例如 `startDebugBossRun(config)`。它不应该在 UI 代码里散落修改 `state`。

建议把成长包定义成数据表，例如 `debugGrowthPacks`。每个成长包明确列出武器、奖励、遗物、证据、牌库和基础数值。

建议复用现有上行图谱素材做 Boss 地图入口。全屏调试台可以复用现有 tuner 视觉，但结构要重做，不要继续把所有数值塞进一个长面板。

## 验收标准

390x844 手机视口下，调试台可以完整完成：进入调试台、选择二幕 Boss、选择推荐通关成长包、调整 Boss 血量、挑战、返回调试台、复制配置。

从调试台直接挑战一幕、二幕、三幕 Boss 时，幕数、Boss、场景、BGM 和推荐成长包都正确。

二幕和三幕 Boss 不能以零成长玩家状态开打，除非用户明确选择“最低成长”或手动清空成长包。

调整 Boss 血量、出手速度、玩家出牌间隔和动作后摇后，下一场战斗必须体现差异。

保存本地预设后，刷新页面再打开调试台，预设仍在，且只出现在调试命名空间。

复制配置得到的 JSON 可以在清空本地存储后重新导入，并复现同一个 Boss、成长包、参数和固定起手。

导入缺字段、坏 schema、引用不存在 Boss 或引用不存在奖励的配置时，系统拒绝导入，不进入战斗，不改写当前有效配置。

调试战斗胜利不会推进正式上行图谱，不会写正式解锁，不会写每日成绩。

战斗内轻量抽屉可以重开本场和复制配置，但不能遮挡手牌主要操作区，也不能让底部 UI 贴近手机 Home 区。

调试台打开、关闭、挑战和返回流程没有控制台错误。

连续划卡性能不能退化。进入调试战后第一次划卡不能触发音频或大图首次加载导致明显卡顿。

导出的调试结果包含胜负、战斗时长、剩余血量、出牌次数、受击次数、四向使用次数、关键失败原因和完整配置。

## 第一版切片

第一版优先做三幕 Boss 直达、推荐成长包、核心战斗参数、导入导出和本地预设。

第一版可以暂时不做完整预设对比页，不做所有普通敌和精英直达，不做图形化曲线，不做多人共享。

只要能让一次完整调参循环在手机上顺畅跑通，就算第一版达标。
