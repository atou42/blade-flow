# Boss Readability And Action Commitment Spec

日期：2026-05-10

本文定义下一版 Boss 动作可读性、错误学习反馈和动作后摇手感。目标是让 Blade Flow 的难度来自“看懂 Boss、选对动作、承担后摇”，而不是来自进度条倒计时或无脑连续出牌。

这份 spec 建立在 `docs/design/action-recovery-boss-read-spec.md` 之上。原文定义了后摇、左划三结果和 Boss 读招矩阵；本文补足视觉语法、错误反馈、手感阈值和验收标准。

## 核心问题

当前 Boss 动作帧数少、姿态变化小，单靠角色图像很难让玩家看出“快刀、慢刀、假抬手、后撤、地裂抓取”的区别。玩家如果只能看进度条，就会学成时间反应，而不是动作判断。

同时，当前后摇体感仍偏轻。玩家快速连续操作时，虽然不是同一个手势穿透，但仍能在短时间内打出多张牌，动作承诺不明显。高收益动作没有足够代价，左划和下划容易重新变成容错保险。

下一版要同时解决这两个问题：Boss 招式必须更容易识别，错误之后必须知道错在哪里，出牌之后必须能感觉到角色正在收招。

## 设计目标

玩家在第一幕 30 秒内应该学会三件事。

第一，红色真确认才是高收益反应点。提前交防守或追击会亏。

第二，不同 Boss 招式有不同答案。快刀适合左划闪反，慢刀适合等破势，后撤适合收招追击，地裂抓取要先离地或破势。

第三，动作有承诺。出牌不是点按钮，而是角色真的挥出一招。重招、左划、空挥和错读都必须让下一张牌慢下来。

## 视觉语法

Boss 动作不依赖高帧数动画，而是使用固定的 2D 平面读招语言。每个招式至少由五层信号组成：Boss 轮廓姿态、核心颜色、方向笔触、危险区域、卡牌短亮。

轮廓负责告诉玩家“Boss 正在做哪类动作”。快刀是窄而尖的前压轮廓；慢刀是宽而重的蓄势轮廓；假抬手是错位残影；后撤是向后拉开的空位；地裂抓取是 Boss 本体少动、玩家脚下变化明显。

颜色负责告诉玩家“现在是不是该反应”。朱红只给真危险和命中确认。紫灰给假动作和不确定状态。金黄给破势窗口。青绿给可追击窗口。白色短闪给完美时机。颜色不能混用，不能让紫灰假动作看起来像真红确认。

方向笔触负责告诉玩家“危险从哪里来”。向下劈用竖向红刀线，横切用横向红弧，地裂用脚下裂纹和吸附圆，后撤用向后的冷色残影，慢刀用厚重下压墨块。

危险区域负责告诉玩家“错了会怎么受罚”。它不是大面积遮罩，而是短暂、清晰、有方向的区域提示。快刀是窄线，慢刀是宽面，横切是弧线，地裂是脚下圆裂。

卡牌短亮只做辅助。窗口出现时只亮一到两张最相关的牌或方向，不能四张一起亮，不能变成自动答案。卡牌提示必须晚于 Boss 预备，接近确认点出现。

## 招式定义

### 快刀

快刀的读法是“短、窄、快、真”。预备阶段 Boss 核心微红，武器方向收紧，屏幕中线出现一条很淡的竖向刀痕。确认阶段出现清晰朱红窄线和白色短闪，持续时间短。命中阶段红线压到玩家身前。

正确答案是确认点左划或格挡。提前轻招可以偷一点伤害，但不能打断。过晚左划只能擦伤或低收益防御。

失败反馈写“晚了，快刀已经贴身”。成功反馈写“快刀确认，闪反打断”。

### 慢刀

慢刀的读法是“重、宽、等窗口”。预备阶段 Boss 身后出现黑红厚墨聚集，武器抬得更高，地面出现宽压影。确认阶段金黄破势裂口出现在 Boss 身前或武器根部。命中阶段宽红墨块下压。

正确答案是中后段下划破势，或上划拖慢。普通左划可以侧退保命，但不能完整打断。提前下划会空挥，提前左划只能低收益。

失败反馈写“慢刀不能被普通侧退打断”或“重招早了，没吃到破势”。成功反馈写“破势窗口，慢刀被截断”。

### 假抬手

假抬手的读法是“先紫灰，后真红”。第一次抬手只出现紫灰残影和半透明弧线，不能出现清晰朱红确认线。Boss 真身要和残影有轻微错位，让玩家看到这是骗招。第二次真确认才切成朱红清线和白色短闪。

正确答案是等第二次真确认再左划。第一次紫灰抬手左划会空闪。保守轻招可以过渡，但收益低。

失败反馈写“空闪，被假抬手骗了，等真红线”。成功反馈写“识破假抬手，真确认闪反”。

### 后撤横切

后撤的读法是“先退，不要追；露空，再追”。预备阶段 Boss 向后拖出冷白或青绿残影，身前出现空位。确认阶段横向朱红弧线扫过前方，追早会撞上横切。收招阶段红弧断开，Boss 后方出现青绿追击线。

正确答案是等收招段右划追身。提前右划是破绽。等它空挥后轻招也可以低收益接上。

失败反馈写“追早了，撞上横切”。成功反馈写“后撤露空，追身命中”。

### 地裂抓取

地裂抓取的读法是“危险来自脚下”。Boss 本体可以少动，但玩家脚下必须出现黑红裂纹、吸附圆和向内拉扯的墨线。预备阶段裂纹是暗红，确认阶段裂纹亮红并收缩。破势窗口用金黄裂口标在地面或 Boss 手势上。

正确答案是早段上划离地，或早段下划破势。站桩下划处决会被抓住后摇。普通左划可以减轻一部分伤害，但不能当作完整答案。

失败反馈写“地裂抓住重招后摇”。成功反馈写“离地避开地裂”或“地裂启动被破势”。

## 动作后摇手感

下一版后摇要让玩家能明确感到“这一招还没收完”。后摇不是禁用按钮，也不是冷却条，而是角色动作承诺。

默认后摇建议调整为：

| 动作结果 | 后摇范围 | 目的 |
| --- | ---: | --- |
| 点击轻招 | 320ms 到 380ms | 保持流动，但不能像连点按钮 |
| 右划命中 | 520ms 到 620ms | 追击有承诺 |
| 右划追早 | 720ms 到 860ms | 追错后明显亏 |
| 上划控制 | 480ms 到 580ms | 换安全时间，但不能无限拖 |
| 普通左划 | 620ms 到 760ms | 保命动作有代价 |
| 完美左划 | 180ms 到 240ms | 读对后获得取消感 |
| 空左划 | 880ms 到 1040ms | 被骗或乱交要明显亏 |
| 下划命中 | 760ms 到 900ms | 重招有重量 |
| 下划空挥 | 1000ms 到 1200ms | 错过窗口的重惩罚 |
| 妙手取消 | 160ms 到 220ms | 奖励正确读招 |

普通动作在后摇期间不允许缓存输入。只有完美左划、破势成功、后撤追身这三类“读对奖励”允许末尾短缓存。缓存窗口为 80ms 到 120ms，只缓存一次。

手牌在后摇期间要整体轻暗，并有轻微下压感。收招末尾可以回亮一点，让玩家知道快能接招。被阻止输入时，当前卡做一次短促回弹，不播放出牌动作，不排队。

## 错误学习反馈

错误反馈必须告诉玩家原因，不只告诉玩家失败。每次破绽最多显示一句短文本，优先使用动作原因。

| 场景 | 反馈文本 | 视觉反馈 |
| --- | --- | --- |
| 快刀左划晚了 | 晚了，快刀已经贴身 | 红线穿过玩家，左划残影被截断 |
| 假抬手提前左划 | 空闪，被假抬手骗了，等真红线 | 紫灰残影散开，Boss 真身留在原位 |
| 慢刀普通左划 | 慢刀不能被普通侧退打断 | Boss 厚墨继续下压，玩家侧退只避开一部分 |
| 下划太早 | 重招早了，没吃到破势 | 金黄裂口未出现，重刃落空 |
| 右划追早 | 追早了，撞上横切 | 玩家冲进横向红弧 |
| 地裂站桩重招 | 地裂抓住重招后摇 | 玩家脚下裂纹收缩，重招被拖住 |

成功反馈也要明确原因。完美左划要显示真确认被切断。破势成功要显示金黄裂口碎开。追身成功要显示青绿追击线贯通。玩家要能从成功反馈里学到“刚才为什么对”。

## UI 和进度条

顶部进度条不再承担主要教学。第一幕普通战可以保留完整条，精英和 Boss 战改为粗略危险段。玩家应该主要看 Boss 视觉提示，而不是盯倒计时。

Boss 状态提示可以保留短标签，但标签只负责确认，不负责解释所有规则。标签文案要短，例如“假抬手”“破势窗”“露空”。不要放长句。

卡牌区要远离手机底部手势条。后摇锁定不能把卡牌压得更低，不能造成误触。手机视口下卡牌底部必须完整可见。

## 音频配合

本文不新增音频素材清单，但要求现有音效按语义触发。真确认用 Boss 真确认音。假抬手用假抬手诱导音。完美左划用闪反成功音。空左划、重招空挥和追早用错读音或后摇拖尾。

声音不能替代视觉。静音状态下，玩家仍然要能看懂招式。

## 调试口径

调试状态必须能读到 Boss 当前动作、当前阶段、是否真确认、是否破势窗口、是否追击窗口、上一次动作结果、上一次后摇、当前后摇剩余、最近五次方向和最近一次错误原因。

新增验收探针需要覆盖四类场景：连续快速出牌、每个 Boss 招式的正确答案、每个 Boss 招式的典型错误、手机视口下的视觉遮挡。

## 验收标准

本地和线上都必须通过以下验收。

1. 390 像素宽手机视口下，五种 Boss 招式在不读长文本的情况下能通过颜色、方向和区域区分。
2. 快刀真确认左划会打断，后摇进入完美值；快刀命中后左划不会打断。
3. 假抬手第一次紫灰抬手左划会空闪，第二次真红确认左划才打断。
4. 慢刀普通左划不能完整打断；中后段下划破势可以打断。
5. 后撤横切提前右划受罚；红弧断开后的右划追身成功。
6. 地裂抓取会惩罚站桩重招；早段上划或破势能给正确反馈。
7. 连续快速操作四张手牌时，普通动作之间必须有肉眼可感知的停顿；不能像连点按钮。
8. 读对奖励动作可以快速接招，但只限完美左划、破势成功、后撤追身。
9. 每一种错误都显示具体原因，玩家能知道是早了、晚了，还是选错方向。
10. 新增视觉提示不能遮挡 Boss、玩家血条、手牌文字和手机底部安全距离。

## 不做范围

下一版不要求重画所有 Boss 帧，不要求新增完整骨骼动画，不要求完全移除进度条，不要求把每张卡做成独立动画，不做新的 Boss 种类。

下一版的重点是建立可读规则。只要低帧 Boss 也能通过颜色、形状、方向、区域和反馈被读懂，就算切片成立。
