# 剩余 Spec 高标准 Goal

本文档把当前 spec 中已经写明但尚未完整落地的内容，收束成下一阶段可执行 goal。目标不是把所有想法一次堆完，而是把 Blade Flow 从“战斗手感纵切”推进到“可反复游玩的内容 alpha”。

## Goal

把 Blade Flow 交付为一个手机竖屏优先、三幕可通关、局内构筑成立、局外成长可信、Boss 可通过动作读招的肉鸽动作卡牌 alpha。玩家每一局都能通过选路、定锚、出牌划向、补牌节奏和 Boss 动作判断主动构造连击，而不是被随机发牌牵着走；打完一局后，本地 profile 会保留有意义的成长，但不会用永久数值碾压破坏战斗判断。

完成时，线上版本必须能让玩家连续玩三局，并明确感受到三种不同打法：高速追身压制、读招闪反反打、破势爆发处决。玩家不读长文字，也能从卡牌外观、方向点灯、Boss 动作、路线颜色、奖励数字和结算反馈里理解当前选择为什么强、哪里有风险、下一步该怎么构筑。

## 当前基线

当前版本是 v0.2.25。已经完成核心战斗、四向出牌、补牌冷却、Boss 压力、连击反馈、国画 UI、本地 5 槽 run save、正式/调试 profile、三幕数值推进、3 个首批配方和基础局外材料。

这不是完整 alpha。当前三幕还是单线重复推进，Boss 仍主要依赖 UI 条和静态形象表达，流派与卡牌亲和只实现了第一层，奖励结构还没有真正形成定锚构筑，长期成长还只是工坊雏形。

## 完成边界

这个 goal 覆盖现有 spec 里影响“可反复玩、能看懂、能构筑”的剩余内容。范围包括上行刀路地图、奖励与定锚、流派卡牌矩阵、Boss 动作读招、局外成长、内容资产、调试器、存档可靠性、性能和部署验收。

不在本 goal 内追求 Steam 完整内容量，不做商业化、不做账号云存档、不做多人、不做完整音频系统、不做大规模剧情文本。所有新增内容都必须服务战斗判断和构筑反馈。

## 必须完成的系统

### 上行刀路

三幕不能只是同一条线重复打。每一幕要有竖屏上行地图，至少展示未来两层选择。路线要分成稳定、危险、锻造、侦察、事件、精英、Boss 预演和 Boss 节点。玩家选择路线后，下一场战斗的手牌节奏、Boss 反制、奖励池和局外证据都要改变。

高危路线必须成立。它不能只是敌人血多伤害高，而要给出可读的风险和更好的构筑机会，例如更强定锚奖励、稀有证据、Boss 残片、诅咒装备或装备调校。玩家应该能主动选择赌命，而不是被难度惩罚。

### 奖励与定锚

每局要有真正的“刃心定锚”。定锚不是局外永久强度，而是玩家在本局通过表现、路线和奖励选择确认一个核心卡向。定锚后，奖励池、卡牌点灯、补牌提招和 Boss 反制都围绕它变化。

奖励界面不能只是随机三选一。每次战斗后至少要体现三类意图：表现奖励回应玩家刚才打得好的部分，构筑奖励加深当前路线，修正奖励帮玩家从偏离路线中回来。高稀有奖励必须同时满足本局表现、局外证据和当前定锚，不能乱打也能拿到核心路线大奖。

### 流派与卡牌矩阵

风暴太刀、镜扇、处刑者三条首发路线要完成核心卡、桥接卡、普通卡的完整矩阵。每张牌都不能被视为废牌，但不同构筑眼里权重要明显不同。核心卡出现时玩家要眼前一亮，桥接卡要能把当前局面接回核心链，普通卡要能稳住节奏但不能抢走主爽点。

同一张卡在不同划向下要有稳定语言。上划负责挑空或冲入，右划负责追身或续压，左划负责闪避、格挡或反打，下划负责破势、蓄势或处决。高收益必须依赖当前手牌、上一招、Boss 状态、距离、破势窗口和本局定锚，不能变成某个流派永远无脑划同一方向。

### 补牌与手牌经济

补牌要继续有冷却和进度条，但需要加入短未来队列。玩家至少能看见下一张或下两张牌的影子，从而决定当前是桥接、等待、续压还是兑现。补牌必须来自真实牌库，不能凭空发玩家想要的牌。

刀势提招要成立。妙手会短距离影响未来牌流，稳手保持正常，空手和破绽不奖励。删牌、换牌、冻结、临时保留、污染牌或诅咒牌要进入局内构筑系统，让玩家能主动塑造牌流，而不是只接受发牌。

### Boss 动作读招

Boss 要从静态图加 UI 条，升级到动作读招。首个完整动作 Boss 以风暴队长为基准，至少有 idle、快刀抬手、慢刀抬手、假抬手、后撤横切、地裂抓取、攻击命中、破势、死亡这些状态。玩家应该能通过身体动作判断该右划追、左划闪反、下划破势，不能只看计时条。

Boss 升级时形象和动作都要切干净，不能残留上一个形象。Boss 死亡和最后一刀必须先播放命中或死亡动画，再进入结算。第二幕开始要加入 Boss 烙印反制，第三幕要有更强的变招压力，但仍然要可读。

### 局外成长

长期成长的主轴是配方、武器学派、上行图谱、训练和高危解锁，不是永久攻击力、永久血量或永久冷却。真实 profile 要保存材料、证据、配方、图鉴、训练课、开放定锚候选、上行图谱进度和名刀记忆。调试 profile 必须单独分仓，支持一键全解锁、固定 seed、设置证据、打开训练、复制当前局复测，并且永远不污染真实 profile。

工坊配方库要从当前 3 个扩展到能支撑三条路线的首批配方。武器学派树要提供路线身份和开局差异，但不能让新玩家第一局像残缺版。上行图谱要把高危分支、Boss 变体和稀有配方作为长期目标。

坏数据必须 fail-close。单个 run 槽坏了只锁这个槽，profile 坏了锁对应 profile，不能清空重建，不能拿默认空档假装正常。当前局引用不存在的配方、路线档案或装备时，要明确显示原因，不能进入脏状态。

### 内容与资产

首批内容要补齐三幕 alpha 所需的 Boss、普通敌人、精英、装备、遗物、契约、战斗证据和地图节点资产。所有资产必须统一到当前国画水墨方向，并且优先服务可读性。看起来帅但玩家看不懂动作、等级、路线或效果，不算通过。

装备至少补齐六件首发候选：风暴太刀、镜扇、处刑者、重力战锤、铳刀、决斗刀鞘。每件装备要有明确打法、弱点、奖励倾向、Boss 反制风险和装备调校方向。遗物、天赋、契约不能只做文字区别，要有颜色、图标、稀有度、类型外观和清晰数值。

普通敌人和精英不是杂兵海。手机竖屏最多同时承载两个主要威胁。每个敌人只教学一个判断，例如追身、格挡、远程压迫、假抬手、破势窗口或处决锁窗。

### UI、反馈与调试器

所有效果说明必须数字化。加伤害、加闪反值、减冷却、加 Boss 烙印、加风险、加掉落，都要用不同颜色和短标签表达。不能用“更强”“更稳”“更适合”这类玩家无法判断的词作为主要说明。

卡牌外观要表达稀有度、类型和路线。不同强化卡、遗物、装备、契约要能靠外观区分，不能只靠文字。方向点灯最多同时强调两张牌，当前 Boss 窗口优先，其次定锚核心，其次连段下一拍，其次桥接。

调试器要覆盖设计师真正会调的参数，包括补牌节奏、未来队列长度、提招强度、Boss 快慢刀时间、假抬手比例、三幕缩放、高危路线奖励、定锚门槛、奖励权重、材料掉落、手牌上限、性能档位。所有预设从简单到地狱必须能一键切换，并且切换后能立刻体验差异。

### 性能与部署

手机竖屏是默认验收环境。新增 sprite、纹理、动效和 UI 后，仍要控制发热和卡顿。需要保留低功耗模式或自动降级策略，避免动画资产把移动端拖垮。核心战斗输入不能因为特效、结算、地图或存档 UI 产生明显延迟。

每次交付必须更新版本号、版本记录和 games.atou.cc 入口说明。线上正式入口仍是 `https://games.atou.cc/combo-card-roguelike/versions/a/`。生成文件不能手改，部署必须走标准流程。

## 分阶段交付

### Alpha 1：构筑成立

先完成上行刀路分支、刃心定锚、奖励三槽、三条路线核心卡矩阵和短未来补牌。这个阶段验收重点是玩家能不能主动构造连击，三局打法是否明显不同。

### Alpha 2：Boss 可读

完成风暴队长动作读招、快慢刀、假抬手、后撤横切、地裂抓取、破势和死亡动画。这个阶段验收重点是玩家能不能不看计时条，仅靠 Boss 动作做出正确判断。

### Alpha 3：长期成长

完成工坊配方扩展、武器学派树、上行图谱、高危分支、训练课、真实/调试 profile 分仓和坏档 fail-close。这个阶段验收重点是打完一局后玩家知道自己长期获得了什么，并且下一局有新的构筑目标。

### Alpha 4：内容池和资产统一

补齐六件装备、首批遗物、天赋、契约、普通敌人、精英、Boss 变体、地图节点和战斗证据资产。这个阶段验收重点是内容变化能被视觉识别，且所有新增内容都服务战斗判断。

### Alpha 5：移动端质量

完成性能预算、低功耗模式、调试器参数补齐、完整移动端验收和线上部署。这个阶段验收重点是手机竖屏连续游玩不卡、不乱闪、不看不清、不发热到影响体验。

## 验收标准

完成时必须能在手机竖屏连续完成三局。第一局偏追击，第二局偏闪反，第三局偏破势或处决。三局的路线选择、手牌权重、Boss 反制、奖励倾向和结算结果必须不同，不能只是数值变大。

玩家在不读长说明的情况下，应该能看懂当前 Boss 正在准备什么、哪张卡哪个方向更香、为什么这次是妙手或破绽、奖励改变了哪个数值、当前装备在鼓励什么打法、局外成长解锁了什么选择。

最后一刀必须先完成视觉反馈再结算。Boss 切换不能残留旧图。出牌后手牌行不能整体闪烁或重建。奖励和存档不能吞错。坏存档不能污染其他槽。调试 profile 不能污染真实 profile。

性能验收要在 390x844 手机视口完成。战斗主循环要稳定，卡牌拖滑、Boss 动作、地图切换、奖励弹窗和存档 UI 都不能出现明显输入延迟。线上部署后，要在 games.atou.cc 正式入口验证可玩、可保存、可继续、可删除存档。

## 证明 Done 的证据

交付时必须留下版本记录、设计变更说明、浏览器验收截图、移动端流程截图、至少一份完整三幕通关记录、一份坏档验证记录、一份性能记录和线上 URL。只说“看起来完成了”不算完成。

如果某项 spec 因为资产生成、性能、交互冲突或范围过大无法完成，必须在文档里明确标注阻塞原因、影响范围和下一步选择，不能用默认值、占位图或模糊文案假装完成。

2026-05-09 验收口径调整：最后一项实体手机 60 秒真实 JSON 因外部物理设备证据无法取得，经用户确认降级为模拟移动端验收。降级验收必须单独成文，明确说明它不是实体手机证据，并保留真实手机发热、手持触感和系统分享未覆盖的风险。降级后的完成证据见 `docs/verification/final-mobile-acceptance-record.md`、`docs/verification/final-mobile-simulated-acceptance-record.md` 和 `docs/roadmap/remaining-spec-completion-audit-v0255-simulated-acceptance.md`。
